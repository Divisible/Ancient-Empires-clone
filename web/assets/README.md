# Knyaz Realms Art System v1

Эталон — последний утверждённый Art Kit. Это reference, не production sheet: не нарезаем изображение и не используем его фон. Production PNG пока отсутствуют; все `src: null`, игра использует прежнюю процедурную графику.

## Подключение

1. Положить прозрачный PNG/WebP в `web/assets/<категория>/<имя>.png`. Категории: terrain, water, roads, bridges, vegetation, mountains, buildings, units, effects, ui. Папки создавать при появлении файлов.
2. В `web/visual/asset-registry.js` указать `assets.<id>.src = '/assets/…'` и проверить метаданные. Файлы отдаёт `asset-files.mjs`; внешние URL, произвольные файлы и выход через symlink за assets не разрешены.
3. Настроить `visualSize` (экранные пиксели до zoom), `anchor` (нормализованная точка опоры 0…1), `tileOffset` (изометрическое визуальное смещение, обычно [0,0]), `depthOffset` (добавка к x+y для сортировки, обычно 0).
4. Проверить на карте, что точка опоры попадает в центр поверхности логической клетки. Размер PNG не определяет footprint. Zoom камеры применяется поверх масштаба ассета.

Пример для одного здания (изменить данные, не renderer):

```js
assets.castle.src = '/assets/buildings/castle.png';
assets.castle.visualSize = [128, 144];
assets.castle.anchor = [0.5, 0.85];
```

Замок ориентировочно занимает 2×2 **визуальные** клетки (128×64 на земле), но его логический footprint остаётся 1 клеткой. Ферма ~1 клетка, юнит ~1 клетка, дерево высотой 1–2 юнита, крупная скала может выступать за клетку. Все параметры отображения собраны в реестре, не в engine.

## Единый арт-стандарт

Ромб земли 2:1 (проекция 64×32 до камеры); свет сверху слева; тени вправо-вниз; прозрачный фон; единая палитра травы, бирюзовой воды, тёплого дерева и серо-зелёного камня. Декоративные края земли не изменяют игровой рельеф. Объекты в соседних клетках могут перекрываться; сортировка — по точке опоры, не по верхнему краю PNG.

Земля: `grass_01`, `grass_02`, `grass_03`, `grass_flowers`, `grass_rocks` — все соответствуют существующему `plain`. Лес: single/small/dense/mixed/edge, горы: rock_small/rocks_medium/mountain/mountain_cluster. Варианты выбираются по координатам; в сохранение ничего не добавляется. Если конкретный выбранный вариант ещё не нарисован — fallback.

Вода/берег: `coast_<mask>`, где биты 1,2,4,8 обозначают землю в направлениях +x,+y,−x,−y; внутренние углы `coast_inner_<mask>` используют диагонали (+x,+y),(−x,+y),(−x,−y),(+x,−y). Маска одной стороны — прямой берег, двух смежных — угловой, трёх — вогнутый охват. Для противоположных берегов выбирается `river_x` или `river_y`. Неизведанные соседи не участвуют. Это полноразмерные визуальные варианты существующей water-клетки, не новые типы terrain. `cliff_<mask>` — прозрачный слой боковой грани на суше, биты обозначают водных соседей. `bridge_x/y` заменяют рисунок существующей road-переправы. Все направления рисовать явно: не вращать освещение спрайта автоматически.

## Владение

У замка и фермы поверх нейтрального рисунка рисуется маленький флаг (`ownership.offset` в display pixels от anchor). Здание целиком не тонируется. При необходимости `ownership.variants[номер_игрока] = { idle: '/assets/…' }` задаёт отдельный файл; остальные владельцы используют нейтральный PNG и флаг. У юнита принадлежность также показывает контур основания.

## Анимации

Для prince и warrior подготовлены `idle`, `movement`, `attack`, `hit`, `death`. `frames` — массив `[sx, sy, sw, sh]` в исходном sprite sheet. Все кадры имеют одинаковые поля, точку опоры и масштаб. `frameMs` задаёт длительность кадра; `loop:false` останавливается на последнем кадре.

```js
assets.unit_prince.animations.movement = {
  src: '/assets/units/prince/movement.png',
  frames: [[0,0,128,160], [128,0,128,160]],
  frameMs: 140, loop: true
};
```

Рендерер сейчас автоматически выбирает idle/movement. API рисования принимает `state` и локальное время `time`; attack/hit/death готовы как формат, но событийный проигрыватель этих состояний ещё не подключён. Это не полноценная система анимаций всего roster. Если нужного sheet нет, используется базовый idle или процедурный рисунок. Ошибка загрузки не мешает матчу; успешная загрузка инвалидирует terrain-cache. Для смены файла с тем же URL обновить страницу; для релизов удобнее версия в имени файла.

## Следующий минимальный пакет PNG

Начать со статических изображений; не нужен сразу весь список возможных вариантов:

| Файлы | Рекомендованный исходный холст / содержание |
|---|---|
| terrain/grass_01.png, grass_02.png, grass_03.png | 128×64, верх ромба, без надписей и сетки |
| water/water_01.png | 128×64, согласованная поверхность воды |
| water/coast_1.png, coast_3.png, coast_7.png | 128×96, прямой/угловой/вогнутый берег; затем остальные ориентации |
| bridges/bridge_x.png, bridge_y.png | 160×128, мост на прозрачном фоне |
| vegetation/tree_single.png, forest_small.png | 128×192 и 192×240, с точкой опоры у основания |
| mountains/mountain.png | 192×224, скала с тенью |
| buildings/castle.png | 256×288, целый замок с нейтральными полотнищами; флаг накладывается UI |
| buildings/farm.png | 160×160, дом/поле/ограда на прозрачном фоне |
| units/prince/idle.png, units/warrior/idle.png | 128×160, один кадр, прозрачность, постоянная точка опоры |

Размеры исходных холстов — экспортный ориентир; метаданные учитывают фактические размеры. Anchor зависит от реальной точки опоры, его необходимо проверить на рисунке, а не слепо копировать значения по умолчанию. Не вшивать HP, выделение, имена и тактическую сетку в PNG.
